# Test runner di VM Lima terpisah

Semua test berjalan di VM Lima (Ubuntu, ext4) dengan repo di-mount read-only dan salinan kerja di `/tmp` VM; macOS tidak pernah menjalankan test destruktif dan tidak pernah ditulis oleh test. Alasan: kode yang diuji justru melakukan operasi destruktif, jadi batas keras di luar triple-layer sandbox (ADR 0007) menghilangkan risiko nyata dengan biaya kecil (satu perintah brew + satu script). Alternatif yang ditolak: Docker (overlayfs di VM bersama, tetap opsi cadangan), test di host (ditolak user), UTM (lebih berat tanpa keuntungan tambahan). Konsekuensi: semantik khusus APFS (case-insensitive, quirk rename) tidak tervalidasi di fase 1 dan dicatat sebagai batasan; smoke test adapter Senpi (Fase 4) diutamakan di VM juga, minimal di host dengan direktori sekali pakai tanpa kasus destruktif.
